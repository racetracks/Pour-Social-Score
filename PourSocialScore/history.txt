=> 3.4.1.53 - Core uplift: fixes, a readable upgrade report, smaller and forward-compatible saves

- Names with a surname (WoW Forever / Camelot): a player called "First Last" is now listed by the whole name from every place you add them (the right-click menu, Blizzard's Ignore, /pss add on your target, players seen for guild rules), instead of as "First" on a realm called "Last" that never blocked. /pss add, remove and expire take two words as the name (a one-word name with a note goes in quotes). Names already saved the old way are repaired once at the first login, and entries that only ever had a first name are listed in chat so you can add them again. The shipped guild lists were rebuilt without these broken names (7634 to 7438 entries).
- Pour Social Score is now in charge of its own ignore list. "Also put listed players on Blizzard's ignore list" is a tick box per player (View/Edit Rule), off by default. Ignoring someone through Blizzard lists them in Pour Social Score with the note "Synced from Blizzard ignore list on <date>" and takes them off Blizzard's list; people already on Blizzard's list are listed and ticked and stay there. Removing a player from either list removes them from both. If you had the old setting on, your listed players on Blizzard's list are ticked for you. Blizzard's own "is now being ignored" lines are no longer hidden.
- The right-click menu on a player has one "PSS" heading with "Block Player" and "Block Guild" (or "Unblock ..." when already listed). Block Guild is not offered without a player in view, for a player with no guild, or for your own guild.
- After every update the first login says in plain words what changed in your saved data: one line per feature, the "SavedVariables performance cleanup" line, then "Saved data upgraded to <version> (step N)." Going back to an older version says so in one line and keeps the newer data. A step that has to wait says so in red and tries again next login.
- Your saved data is much smaller and safer across versions. Guild members, counts, player switches and the block log save only what is not obvious (on a large save the guild file is about half its size and about 290 KB less is held in memory after login), each guild rule keeps at most 1500 stored members, and the Player Ignore List is saved as one record per person. Data a newer version saved is kept when you go back and forth. A rule this version cannot use is kept, not applied, named at login, and "/pss export unused" copies it out. Export strings carry every field and older versions still read them. Every number you see is unchanged.
- Custom chat filters have a permanent id: editing a filter keeps its history and counts, and Copy starts a new one.
- Fixes: ignore list expiry now happens by itself (at login, after combat once a day, and when the window or /pss list opens); the Unit Menu and LFG options apply without a /reload; [talent=N] works as a filter tag; Import with Replace keeps the default guild lists; the party warning names only who is in your group now; /pss list no longer errors on an entry with no note; errors in the window or a guild scan are shown once in chat.
- The window: a long line in a guild list's detail pane wraps and pushes the lines below it down; the Chat Filters tab redraws at most 4 times a second while lines are blocked; guild rows dim as soon as their rule is turned off; Dark right-click menus show every entry up to 400 pixels tall and as wide as the longest entry; Modern falls back to Classic when any of its art is missing. The copy and import box now shares its text area with the Chat Filters box.
- Lighter and quicker: removing a player, member or filter no longer loads the block history (their lines are taken out the next time it opens); garbage collection runs only on events, never on a timer; target, mouseover and /who events are heard only while they can be used; a blocked line makes less garbage; rarely used parts load only when needed (about 63 KB less at login); the reload popup, unused code and /pss test are gone.
- Going back to an older version after this update is not recommended. 3.4.0.29 does not show your Player Ignore List (the list stays in the save) and deletes your custom chat filters and their counts at its first logout; 3.4.1.50 and older may show a few more guild members until the shipped lists load. Players you add while on an older version are not kept when you come back to this version.

=> 3.4.1.52 - Core uplift: sparse saves, core performance, window tidy

- Your saved data is much smaller. Guild member records, block counts, player switches and the block log keep only what is not obvious, so the guild file is about half its size and the addon holds roughly 290 KB less in memory after login on a large save. The first login after the update tidies the save once (the report shows "SavedVariables performance cleanup"). Every number you see is unchanged.
- Each guild rule keeps at most 1500 stored members. On Camelot, names saved as "First-Last" by the old unit lookup are repaired once: merged into the shipped lists or an existing record, or renamed to "First Last". Entries that only ever had a first name are listed once in chat so you can add them again.
- Custom chat filters now have a permanent id. Editing a filter keeps its history and counts, and Copy starts a new one.
- Going back to an older version afterwards: 3.4.1.50 and older may show a few more guild members until the shipped lists load, and 3.4.0.29 will not show your Player Ignore List or custom filters that have an id. Your data stays in the save.
- Less work in the background. Garbage collection is driven by events only (no timers), the addon listens for target, mouseover and /who events only while it can use them, a blocked chat line allocates less, and a full outbox trims in batches. The reload popup, a dead compatibility file and about 20 KB of unused code are gone, and /pss test is removed.
- Several rarely used parts (player list rows and sorting, the save check, the Scan All planner, Camelot repair) load only when something needs them, so about 63 KB less sits in memory at login.
- The PSS window: the same look in Modern, Classic and Dark, with its logic moved out of the drawing files and fewer redraws when a block is counted. The copy and import box shares its text area with the Chat Filters box, so check it once in your look.

=> 3.4.1.51 - Player list: one record per entry

- Your Player Ignore List is now saved as one small record per person instead of eight lists that had to be kept in step. Notes, expiry, added date, faction and the other details stay attached to the right person, and removing someone is one step. Your saved data is moved over once at the first login (the report shows "Player Ignore List: N entries moved to one record each"). Nothing you can see changes. Going back to an older version afterwards will not show these entries or notes.

=> 3.4.1.50 - Core uplift S2: member field accessors

- A guild member's block total is now never read lower than its counts added up.

=> 3.4.1.49 - Core uplift S1: purge by owner

- Removing a player, a guild member or a chat filter, or resetting their block history, no longer loads the block history in the background. Their lines are marked and taken out the next time the history opens, so someone you remove and list again shows only their new lines.
- Clearing one person's or filter's lines is much faster (a few hundredths of a millisecond instead of several milliseconds) and makes no garbage.

=> 3.4.1.48 - Core uplift U3 fix: /pss export unused and Export

- Fixed in 3.4.1.47's test: "/pss export unused" did nothing, and the Export button on the Import/Export tab gave no string. One window file used a name it had not declared, so the window's files stopped loading part way. Both work again.

=> 3.4.1.47 - Core uplift U3: forward compatibility

- Your saved data now works across versions in both directions. From this version on, going back to an older version and forward again keeps everything a newer version saved, even the parts the older one does not know.
- A saved rule this version cannot use (a chat filter with a tag from a newer version, a guild rule from a newer version, or a setting it does not have) is not applied and is kept unchanged. The first login after a version change says how many there are, per feature. "/pss export unused" copies them so you can keep them outside the game; a version that knows them can import them.
- Export strings now carry every field of a player, guild rule and member, including any from a newer version, and importing keeps them. Older versions still read the new strings.
- Block history and 24-hour counts saved by a newer version are kept as they are. Blocks are still counted, but that session's lines are not added to the history.

=> 3.4.1.46 - Core uplift U2: the upgrade report

- After an update, the first login now says in plain words what was upgraded in your saved data, all at once: a line "Updated from <old version> to <new version>. Upgrading your saved data:", one line for each feature that changed (Chat Filtering, Player Ignore List, Guild Ignore List, Managed Communities, Block History, Options), the "SavedVariables performance cleanup" line every time (what it tidied, or "nothing to tidy"), then "Saved data upgraded to <version> (step N)." as before. The next login says nothing. A brand new save says nothing either.
- Going back to an older version than the one that last wrote your saved data now says so in one line ("Running X, older than your saved data (Y). Nothing was upgraded.") and keeps the newer version's record, instead of quietly overwriting it.
- If an upgrade step has to wait (for example a folder is missing), a red line says which step paused; it tries again at the next login.
- The note about old folders that are safe to delete is now on the cleanup line.

=> 3.4.1.45 - Upgrade step registry (U1)

- Settings that no version reads any more are kept in one list and removed at every login; only settings named there are ever removed, so data written by a newer version is kept.

=> 3.4.0.29 - The new Pour Social Score window

- One new Pour Social Score window replaces both old windows (the classic PSS window and the EllesmereUI window). /pss (also /pss gui, ui or eui), the Addon Compartment and your Friends or Social window open it; /pss help lists the chat commands.

Select an entry to see it beside the list: Summary (its counts and pies), Event History and View/Edit Rule. With nothing selected you see the whole list's totals for this session, the last 24 hours and all time, and by type.

- Right-click any row for its menu. Removing anything now asks first.
- Player Ignore List: Player Search (a /who for a name, tick who to add), Add Player with an empty box adds your target, and Prune removes entries older than the days you choose.
- Guild Ignore List: Managed Communities, your guilds and the Guild Exclusion List in one grouped list, with Scan All, Guild Search and a members view per guild.
- New defaults for everyone on your lists: no ignore response is sent, no decline messages are shown, and their duels and trades are declined. Any player, guild or guild member can be an exception (tick boxes on View/Edit Rule, or in the row's menu).
- Safer in instances and encounters: names and chat details the game hides from addons are checked first and skipped quietly. A listed player is still blocked when only their message is hidden.
- Guild invites from listed players are declined through the game's own decline call only.
- Lighter: the window loads only when opened, listens only while open, and lets go of what it read when closed; busy guild lists update far more cheaply as lines are blocked.
- Upgrading: your lists, rules, counts and history are kept. The old EllesmereUI integration setting and the old window's sizes and column widths are removed. If PourSocialScore_EllesmereUI or PourSocialScore_UI is still in your AddOns folder you are told once at login; delete them.

=> 2.0.40 - Fix: background cleanup that never finished; less garbage per blocked line

=> 2.0.0 - One chat-block core

File layout
- PSS_ChatBlock.lua      The single chat-block function. Every chat line, invite, duel and trade goes through it.
- PSS_PlayerIgnoreList.lua  Player Ignore List logic (list, sync, /pss, per-player switches) + its block source.
- PSS_GuildIgnoreList.lua   Guild Ignore List logic (rules, members, scans, /pssguild) + its block source.
- PSS_ChatFilters.lua    Chat filter rules and the filter engine, registered with the core as its text check.
- PSS_Options.lua        Options registry, the Options tab, and the scoped option resolver.
- PSS_ImportExport.lua   Import/Export tab and the export string format.

How a chat line is decided (OlympusMute model)
1. One filter on every chat event; the decision is cached per line, so a line shown in 5 chat windows is decided and counted once.
2. System lines (ignore-list sync noise, logins of listed players) and NPC lines are checked first.
3. People: the sender is looked up once (GUID first, then a normalised name key) in BOTH lists. The lists are merged:
   if ANY list blocks that message type for that person, the line is hidden. Lookups are hash-table (O(1)),
   so list size does not matter (tested: 20,000 guild members + 3,000 players, ~55 microseconds per line).
4. Ignored servers.
5. Chat filters (text rules) last. Staff (GM/DEV) messages are never text-filtered. You and your own messages are never blocked.
When a person becomes blocked, their earlier lines are removed from the chat windows, and a party invite from them that is still open is declined.

Per-person message types (the same on both lists)
- Whispers, Party invites, Guild invites, Party/Raid chat (includes raid warnings, instance chat); world chat is always blocked.
- Player Ignore List: switches W / I / G / P on each row.  Guild Ignore List: guild columns + per-member Allow columns
  (new "Allow Guild Invites" column; older saves copy the Group Invites setting).

Options
- Every option has a value for all characters, plus an optional override for the current character (Options tab, right column).
- Options marked * can also be set per guild (right-click a guild row) and per person (right-click a player row or a guild member):
  Send ignore response, Show declines, Decline duels, Decline trades.  Most specific wins: person > guild > character > all characters.

Import/Export (tab between Chat Filters and Options)
- Export any of: Player Ignore List (with switches, notes, overrides), Guild Ignore List (optionally with captured members),
  custom chat filters, built-in filter on/off, options.  Import with Merge (adds what is missing) or Replace (with confirmation).
- The string is "PSS1:<checksum>:<data>". It is read as data only (never run as code) and is rejected if damaged or edited.

Behaviour changes to know about
- CHAT_MSG_COMMUNITIES_CHANNEL is now covered as world chat.
- Your own outgoing whispers are no longer hidden.
- Duels and trades are now also declined from guild-list members (both can be turned off, also per guild/person).
- The "Add Player" button now works (it called a missing function before).
- Chat bubbles are not filtered.

- Summary updates live. Totals were previously counted from a 100-entry history, so they stopped moving once a guild hit 100 blocks; counters are now kept separately and are not capped.

- Allow Group Invites / Allow Whispers / Allow All Chat checkboxes are bound directly to the member record shown on the row. The old code re-looked the player up by name and, when realm spellings differed, saved nothing and then un-ticked the box. Member lookup for blocking is realm-spelling-insensitive too ("Aman'Thul" / "AmanThul" / "Area 52" / "Area52").
- Allow All Chat covers party/raid AND world chat; Allow Whispers covers whispers; Allow Group Invites covers party and guild invites.
- History and counts are stored on member records, so when a member moves between guild rules (Add Guild promotion, or the scan reconcile) their blocked history moves with them; duplicates are merged and de-duplicated.
- A guild invite from an unscanned member of an ignored guild is now caught (the invite carries their guild name) and the inviter is added to that guild rule. The old handler also overwrote the member's real guild with the rule name.
- Existing saved data is migrated on login: duplicate history entries from the old multi-count bug are collapsed and counts rebuilt from them.

PSS now has an automated expiration system which allows players to be automatically removed after a specified number of days.  This can be set using the UI or chat commands, and a default value for all newly added ignored players can be set too!

"/pss defexpire days" can now be used to set the number of days that newly ignored players will remain on the list before they are automatically removed.

	"/ignore mytoon 30" This will ignore mytoon with a 30 day expiration time
	"/ignore mytoon this person is mean!"  This will ignore mytoon and set their note to "This person is mean!"
	"/ignore mytoon 30 this person is mean!" This will ignore mytoon, removing them after 30 days, and setting their note to "this person is mean"
